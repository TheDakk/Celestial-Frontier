CELESTIAL FRONTIER V2
Pixel art reference pack and generation prompts

HOW TO GENERATE ANOTHER CONCEPT

In ImageGen or an image generator with reference-image input, attach an existing game painting or screenshot for subject accuracy and a PNG from this pack for the pixel-art direction. State which image is the anatomy, environment, or layout reference and which image defines the style. Use the master prompt below and add one brief per generation. Keep approved silhouettes, markings, palette roles, exact labels, and camera views explicit.

For revisions, attach your accepted reference plus the latest draft. Ask for one change at a time and name the details that should stay fixed. Reuse the same creature sheet for the battle screen and the Compendium so a species remains recognizable across both views.

MASTER PROMPT

Create an original Celestial Frontier v2 visual-development reference in the attached approved pixel-art direction. Treat the existing game paintings as source reference for anatomy, landscape and object identity, and the approved pixel-art concepts as the style reference. Redraw the forms with deliberate square pixel clusters, short stepped diagonals, selective dithering, a limited set of hue-shifted flat colors per surface, crisp nearest-neighbor-style edges, and enough large shapes to read on iPhone. Aim for the apparent density of a detailed late-16-bit game, about a 400×225 logical image for landscape or 225×400 for portrait, with modular, sparse navy interfaces, cyan selection accents, brass marks and readable warm-ivory bitmap letters where requested. Keep species-specific silhouettes, functional anatomy and signature markings. Avoid smooth gradients, painterly or photo texture, blur, anti-aliasing, pixelation filters, excessive detail, watermarks and extra labels. Deliver one standalone full-bleed concept image.

FROM CONCEPT TO GAME ASSETS

The five PNGs are generated visual references. The grid targets in the prompts describe visual density. For game assets, author the art at native size on a real square grid, limit colors with a working palette, and preview at integer zoom as well as actual phone display size.

For a biome, prepare separate background ridges, trees, water, encounter ground, foreground plants, and weather elements. Anchor the playable ground so creature contacts and shadows agree with the scenery.

For a procedural creature, start from the game's resolved body plan and full immutable genome. Record the silhouette, compatible limb and tail parts, attachment and contact points, markings, and palette roles for that family. Draw the parts and key poses on the same pixel grid. Version the rules and sprite sets so the same supported genome and art version reproduce the same creature. Use shared trait and identity data for icon, portrait, and battle sprite. Generate reference images in the authoring workflow, then use deterministic assembly during play.

Check a small set of contrasting genomes in idle, approach, attack, hit, and recovery at phone scale. Look for unrecognizable silhouettes, missing or doubled parts, sliding feet, visible seams, and markings that jump between frames. Compare repeat renders of the same genome and check that the inherited traits intended to be visible are legible in both battle and the gallery.
