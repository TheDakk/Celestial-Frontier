# Canonical landfall snapshot export

Matches implementation as of September9,2026. This isolated Node authoring entry
calls the real CF1 resolver, canonical world roster, biome projection and
`buildLandfallAppearanceSnapshotV1`. Its first supported adapter is Earth epoch0.
It creates no route, ownership, save, model, image or browser UI.

The application snapshot owner requires an actual branded live roster, then uses
the existing exact Earth admission over the full request and all19 source rows.
It exports deeply frozen detached data: version/recipe ID, full address/ecology/
environment/profile bindings, all19 ordered genomes, static presentation inputs,
and the existing six complete display identities/families/composition anchors.
Preview limits are absent. All underlying game fields remain unchanged.

The exported data intentionally has no runtime or type-level canonical authority.
Parsing it does not recreate the private roster WeakSet membership, and passing
it back to the application builder is refused. It is an appearance input, not a
save import, capture grant, shared-image codec or promise of identical GPU pixels.
There is no wall clock, procedural RNG, new season simulation or arbitrary-world
fallback in this module. The wider time/sharing proposal remains separate.

`export.mjs` holds the V2 workspace build lease, bundles this pure entry into a
new isolated directory using the existing locked Rolldown, calls its producer,
and records every transformed source plus package/lock hashes. It checks source
stability, emitted bytes and stable snapshot serialization. The original game
build and active Vite process are untouched. Bundle/lease cleanup precedes PASS.
Every output directory must be new; failures retain their own manifest.

```sh
node tools/with-toolchain-lock.mjs --label landfall-snapshot -- node port/v2/tools/landfall-snapshot/export.mjs NEW_OUTPUT_DIRECTORY
```

The browser image proof invokes this producer before creating its loopback server.
It consumes the detached request/roster plus versioned snapshot hash/display plan,
and checks all recorded source hashes again after its run. It no longer extracts
JSON literals from TypeScript source using regex. The fixed Earth prompt and
separately pinned model, references, preprocessing, seed, steps and dimensions
remain generation-recipe concerns. Other worlds need explicit reviewed adapters.

The actual-play integration point remains `requestSurfaceVista` in `main.ts`,
where the game already owns a current proven roster/request and cancellation
checks. This batch does not mount generated output there or start model downloads.
`qualityAccepted:false` remains: canonical inputs do not qualify the painting.
Current raw checks and retained first failures live in the September9 continuation
audit packet; full changed-head admission and physical devices remain separate.
