## Implemented boundary

The optional `?localai=1` development preview now uses the ordinary game Land action, Survey
card and Notifications. After the existing landing transaction publishes its exact durable
route and scene, a separate page-owned queue starts the painting. Training, refused landings,
recovery-only outcomes, replaced authority and stale rendered identities cannot start it.
The AI job never holds or changes the landing save transaction, awards, risk, genomes or roster.
Navigation does not cancel generation; an explicit Cancel does. Completion never auto-navigates.
View landfall uses the existing proven navigation and ordinary landing path, then checks the
current full canonical snapshot before mounting the retained original. An intervening navigation
during its storage read invalidates that View intent.

One job runs at a time, with at most three waiting and twelve terminal metadata rows. Jobs do
not survive page closure. Exact originals do survive reload in the separate origin-local
`cf-ai-landfall-originals-v1` IndexedDB database. Each immutable original binds its full admitted
recipe, world, environment, ecology epoch, source snapshot digest and image SHA256. Original and
latest index commit atomically; a fresh read and rehash must pass before Ready/notification.
Quota, abort or verification failure cannot report Ready. No original deletion/eviction API exists.
This is not an outside-origin backup: browser site-data deletion can remove these pixels.
Lookup currently includes the full model recipe. A changed recipe after reload does not
automatically discover an older original, though the bytes remain retained. A separate full-identity
index is needed for cross-recipe discovery; this batch adds no deletion or save-schema change.

Progress comes from actual ordered text/reference/denoise/decode stages. The job reserves its
last percent for durable original retention. ETA estimates remaining drawing only after two
measured denoise completions and explicitly adds final processing. No fixed latency promise.
Originals remain native 1024×576 PNGs; display contains the complete painting in the existing
measured scene band, with the same 12px clearance and no UI relocation or image cropping.

## Model delivery

`local-model-delivery.ts` implements explicit browser installation/resume into OPFS. The pinned
twenty-file model totals **6,691,020,416 bytes (6.23 GiB)**, separate from runtime libraries, retained
art, saves and live GPU/RAM. No player shipping model or mandatory download has been selected.
The preview's existing developer cache is freshly verified before serving; it performs no
inference. Browser workers execute the model locally. No remote generation service is involved.

Browser installation uses immutable 1 MiB chunks, serialized Web Locks, exact HTTP Range resume,
full-file incremental SHA256, readback, and atomic manifest-bound readiness markers. Partial or
corrupt data never becomes ready. A corrupt attempt is preserved; an explicit fresh attempt is
separate. Quota estimates include all origin usage plus headroom, and actual write errors still
stop admission. Delivery does not materialize a multi-GB shard in one JS buffer; ORT's later
allocations remain a separate device qualification requirement. Switching storage while painting
or starting a painting during installation is refused. Retrying an older failed/canceled recipe
after changing model selection gives an explicit land-again notice before any work starts; it
does not silently rewrite the recipe or use the previously selected model.

The normal preview checks actual secure-context, WebGPU/f16, OPFS, Web Locks and quota support.
These capabilities do not establish phone performance, buffer fit, thermal behavior or storage
durability. No UA-derived device tiers or physical-mobile success are claimed. Browser delivery
uses the original pinned model; the optional 336 MiB desktop Q8 derivative stays separate.
