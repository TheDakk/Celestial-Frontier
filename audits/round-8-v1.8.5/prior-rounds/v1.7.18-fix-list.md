## Critical

### CF1718-01 — `startTutorial()` references an out-of-scope helper; a mid-training reload destroys the Compendium permanently

The v1.7.18 notes say restarting training *"truly leaves your expedition untouched … **even if you
reload mid-training**."* That is the one path that loses everything.

`_capA` is declared with `const` **inside `function loadSave()`**:

```js
function loadSave(){                                    // 16217
  …
    const _capA=(a,n)=>Array.isArray(a)?a.slice(0,n):[];   // 16229 — block-scoped to loadSave
```

`startTutorial()` calls it from a different function scope, in the branch that runs **only** when a
snapshot was rehydrated from the save:

```js
if(_tutSnapPending){
  const p=_tutSnapPending; _tutSnapPending=null;              // 24609 — consumed BEFORE the throw
  _tutSnap={…
    codexSnap:_capA(p.c,1500).map(…)                          // 24614 — ReferenceError
    cargo:_capA(p.ca,200), cgx:_capA(p.cx,200), items:_capA(p.it,300),   // 24616
```

The boot site swallows it:

```js
setTimeout(()=>{ try{ startTutorial(); }catch(_){} }, 800);   // 25534
```

**Proof — A/B on two saves identical in every field except the presence of `tsnap`:**

```
save WITHOUT tsnap  →  tutbox true,  body.training true,  step 1 / 21
save WITH    tsnap  →  tutbox false, body.training false, no step at all
```

`body.training` is added at line 24638, *after* the throwing line — so the class never lands,
confirming execution stops inside that branch.

**Measured consequence, driving the real UI:**

```
t0  veteran save                  codex 3   cargo 3   items 3
t1  Restart tapped, training runs  codex 0   (snapshot rides the save as `tsnap`, 3 entries)
    → reload the page here
t2  after reload                  codex 0   tutbox absent   tut 0   tsnap still present
t3  ~1s later, first autosave     codex 0   tsnap GONE      tut 0
```

The kill is in that last step. `doSave` only writes `tsnap` while `_tutHook` is set (16189); since
`startTutorial` threw, `_tutHook` is null, so the very next autosave writes `tsnap: undefined` and
**erases the only copy of the expedition**. `cfcc_save_v2_bak` is no help either — it is rewritten
at load time with the already-wiped save. The player is left permanently at `tutDone === false`,
with an empty Compendium, and every subsequent boot re-enters the same branch.

**Fix:** hoist `_capA` to module scope (it is a three-line pure helper), or inline
`Array.isArray(x)?x.slice(0,n):[]` at the four call sites. Then replace the bare `catch(_){}` at
25534 with one that at least reports — a silent catch around a restore path is what let this ship.

## Fixes that do not execute

### CF1718-02 — The victory-tie fix reads `A.genome`, which does not exist; behaviour is unchanged

```js
const A=mine.stats||battleStats(mine.genome), B=theirs.stats||battleStats(theirs.genome);   // 17590
…
: (((hashInt(hashInt((A.genome?A.genome.seed:1)>>>0,0x9E37,0x71EB),
              (B.genome?B.genome.seed:2)>>>0,0x85EB)>>>9)&1)===0?'A':'B');                   // 17670
```

`A` and `B` are **stat blocks**, not combatants. Printed directly from a live duel:

```
res.A has .genome?  false      A keys: vit,fer,res,agi,ins,total,ab
```

So both ternaries always take their literal branch and the "cascaded seeded coin" evaluates to a
compile-time constant — `hashInt(hashInt(1,…),2,…) >>> 9 & 1 === 0` → **always `'A'`**. Side A is
always the player at all three call sites.

Measured, 4,000 seeded duels with identical stat blocks on both sides, v1.7.18's own `runDuel`:

| mirror match | reached the round cap | exact-fraction ties | **player won** |
|---|---|---|---|
| bulwark tank | 100% | 58.6% | **79.9%** |
| low-ferocity | 100% | 64.9% | **82.8%** |

Byte-identical to v1.7.15. **Fix:** use the seeds that are already in scope on the line above —
`mine.genome.seed>>>0` and `theirs.genome.seed>>>0` — exactly as the working initiative coin does at
17601.

### CF1718-03 — The touch-target block was added to the first `<style>` element and loses the cascade

The new rules sit at lines **26–32**, inside the `<style>` that opens at line 17. Every base rule
they need to override lives in the *second* `<style>`, which opens at line 58. All are
ID-specificity, so later source order wins.

| new rule (line) | overridden by | net effect |
|---|---|---|
| `#bell,#setbtn,#helpbtn{width:44px;height:44px}` (28) | `#setbtn` 204, `#bell` 307, `#helpbtn` 1295 — each `34px` | **dead** |
| `#recbtn{width:44px;height:44px}` (29) | 1931 `@media(min-width:901px){#recbtn{36px}}` | **dead** |
| `#namein,#searchin{font-size:16px}` (30) | 339 `#searchin{font:11.5px …}` — the `font` shorthand resets `font-size` | **dead for `#searchin`**; iOS still zooms on focus |
| `#topbar{padding-top:max(6px,env(safe-area-inset-top))}` (31) | 112 `#topbar{padding:14px 18px}` — the shorthand resets `padding-top` | **dead** |
| `#chbtn,#codexbtn,#logbtn,#cargobtn,#pcdxbtn{min-height:44px;…}` (27) | 1924 re-sets `padding` only | **partial — `min-height` survives** |

**Measured on the 21-device sweep**, the three touch devices in the 901–1599 band:

```
device          v1.7.15   v1.7.18
surface-pro  912   258  →   201
ipad-pro-13 1024   231  →   201
ipad-land   1180   231  →   174
```

Real improvement, from the one rule that survived. But the four the analysis predicts are dead are
dead, measured:

```
#bell     34 × 34     #setbtn   34 × 34
#helpbtn  34 × 34     #recbtn   36 × 36     #searchin  236 × 30
```

**Fix:** move the block into the second `<style>` (after line 1958), and write `#topbar` as a full
`padding` shorthand plus a `padding-top` override.

Two more blocks have the same defect from the same cause:

- **CF1718-04** — `.pby{…-webkit-line-clamp:2;white-space:normal}` at line 48 is out-specified by
  `.psig .pby{…white-space:nowrap;text-overflow:ellipsis}` at 1170, and `.pby` is only ever emitted
  inside `.psig`. So the clamp never engages — **and it is now worse than before**: `display:-webkit-box`
  *does* apply (1170 sets no `display`), and `-webkit-box` is not a block container, so
  `text-overflow:ellipsis` stops working. Long titan titles are hard-clipped mid-word with no "…".
  Fix: change the selector to `.psig .pby`.
- **CF1718-05** — `@media (min-width:901px) and (max-height:500px){#codex,#log,#chpanel,#records,#tray{max-height:…}}`
  at 51–53 is overridden by the later plain `#id{max-height:…}` rules at 315, 696, 1312, 1406, 1506.
  Landscape phones still overflow exactly as before. Same one-line fix.

## New regressions

### CF1718-06 — `stats.hybrids` is double-counted on every training restart — HIGH

`_tutCleanup` restores stats first, then re-stores the Compendium:

```js
for(const k in _tutSnap.stats) stats[k]=_tutSnap.stats[k];                       // 24496 — hybrids := 40
…
for(const e of (_tutSnap.codexSnap||[])){ try{ _storeSpecies(e.g, e.f, e.w, true); }catch(_){ } }   // 24515
```

`stats.hybrids` is **not persisted** — it is derived at load by `onSpeciesStored`, which increments
*before* its `_loading` guard:

```js
function onSpeciesStored(entry){
  gameEvent('species', {id:entry.id||null});
  if(entry.hybrid) stats.hybrids++;      // ← runs even during the restore
  …
  if(_loading) return;
  checkAch(); renderRank(); queueSave();
}
```

`_loading` is false inside `_tutCleanup`, so a veteran with 40 hybrids graduates a restarted
training with **80**; twice with **120**. It feeds the rank score and the `gene10`/`gene50`
achievements, which `checkAch()` — also called per entry — will falsely unlock with a toast. The same
loop fires `checkAch()`, `renderRank()` and `queueSave()` up to 1,500 times synchronously on one tap.
**Fix:** wrap the restore loop in `_loading=true; … _loading=false;` and re-apply the derived counters
afterwards.

### CF1718-07 — The Earth Atlas entry is destroyed and rebuilt as a stub — MEDIUM

`startTutorial` now deletes it (correctly, to fix CF1715-02):

```js
try{ logMap.delete('p133'); if(homeId==='p133') homeId=null; logCountEl.textContent=logMap.size; }catch(_){ }   // 24632
```

but `_tutEnsureEarth` only re-adds `if(!logMap.has('p133'))`, and the replacement is hard-coded
(24533). Lost on every restart: the ☆ favourite flag (which drives the favourites filter and the
`curator` achievement), the entry's original timestamp (Earth jumps to "most recent" in the Atlas),
any stored thumbnail, and any custom badge or sub-label. That contradicts the same release note this
round is built on. Minor companion: unlike every other `logMap` mutation site, 24632 does not call
`renderLog()`, so an open Atlas keeps painting a stale row. **Fix:** stash the entry before deleting
and re-`set` it rather than building a stub.

### CF1718-08 — `body.training #panel{z-index:58}` hides the tutorial spotlight ring — MEDIUM

Line 1873 raises the survey card above `#tutspot` (z-index 49, line 1248), which only rises to 59
via `.overtop` — applied on the `sheet` step alone (24254). Three steps spot targets inside the
panel: `survey-tour`, `atlas-add` (`#panel [data-act="add"]`) and `land` (`#panel [data-act="landcta"]`).
For the two button targets the whole ring now renders *under* the panel's own glass. Two of the 21
lessons lose their visual affordance — and `atlas-add` is the step the last round's critical was
about.

**Measured live at step 4/21:**

```
#tutspot   z-index 49   at (635,232) 194×43   class ""   ← .overtop not applied
#panel     z-index 58   at (626,64) 300×574              ← fully contains the ring
elementFromPoint(ring centre) → "act primary"            ← the button, inside #panel
```

The ring's box sits entirely inside the panel's, and the panel paints nine layers above it.
**Fix:** raise `#tutspot` to 59 for the duration of training.

### CF1718-09 — The snapshot round-trip skips every loader sanitizer except the genome one — MEDIUM

The comment at 24606 claims the snapshot "rehydrates here through the same sanitizers as the loader."
Only `codexSnap` does:

```js
pstats:(p.ps&&typeof p.ps==='object')?{...p.ps}:{...pstats},     // 24611 — raw
essence:Number.isFinite(+p.es)?+p.es:essence,                     // 24613 — no clamp
```

The loader clamps `pstats` to 1–330 per key (16329) and `essence` to 0–1e9. Via `tsnap` neither is
clamped, so an edited save yields an unbeatable player; and a *truncated* `tsnap.ps` (`{}` passes the
`typeof` test) leaves `pstats.vit` undefined → `hpMaxFromVit()` returns `NaN` → the HP bar and every
duel break, silently, inside the bare catch at 24487.

### CF1718-10 — `_restoreFocus()` on Escape is a no-op for 10 of 13 overlays, and can steal the correct target — MEDIUM

`_focusReturn` is assigned in exactly one place — line 25068, inside a delegated click handler that
fires only for a `PANELS` entry's button. Of the 13 ids in the Escape stack (5585), only `setpanel`,
`guidebox` and `primebox` are `PANELS` members; the other ten never set it, so `_restoreFocus()` finds
`null`. Worse, it can consume someone else's: open the Compendium via `#codexbtn` (sets
`_focusReturn`), tap a species to open `#reveal`, press Escape — line 5598 focuses `#codexbtn` and
**nulls `_focusReturn`** while the Compendium is still open, so the second Escape lands on `<body>`.
**Fix:** record `document.activeElement` when each modal opens.

### CF1718-11 — `sysSeen` off-by-one loses one legitimate First Arrival — LOW

```js
sysSeen.add(seed);
if(sysSeen.size>=900) return;      // 15471
```

`add` runs before the test, so on the 900th distinct system the guard fires and the player silently
loses that arrival's +2 ☄, its `stats.arrivals` tick and its toast. Should be `>900`, or test before
adding. (Secondary: removing the eviction makes `sysSeen` unbounded in the save — consistent with
`landed`/`surveyedSet`, but it is new growth.)

### CF1718-12 — `chWeek` has no upper clamp, so a forward clock jump freezes the weekly slate forever — LOW

The rollback exploit is genuinely closed (`if(wk>chWeek)`, 23662). But `chWeek=num(data.chw,-1)` at
16402 accepts any number. One forward clock jump banks a large `chWeek`, and the weekly board then
never rolls again — `_chWeekly()` is seeded on `chWeek`, so the same three charters stand forever.
Under the old `!==` this self-healed on the next boot. **Fix:** `chWeek=Math.min(num(data.chw,-1), _chNow());`

### CF1718-13 — The canvas a11y change contradicts the comment above it, and `role="application"` is heavy — MEDIUM

```js
/* a11y-churn mitigation (Nick's Edge crash dumps: renderer died in
   UnrecoverableAccessibilityError while assistive tech was attached).
   … hiding it from the a11y tree removes the highest-churn node … */
try{ cv.setAttribute('role','application');       // 2337–2344
  cv.setAttribute('aria-label','Star map. Arrow keys cycle bodies, …'); }catch(_){ }
```

The comment explaining why `aria-hidden` was set is retained verbatim while the fix removes it — so
either the comment is stale or the Edge renderer crash is back. Worth a decision either way.
Separately, `role="application"` tells screen readers to forward *all* keystrokes and suppress browse
mode, and this element is the page's first tab stop — an AT user tabbing in loses their normal reading
commands across the entire map. `role="img"` with the same label, or `role="application"` applied only
on focus, meets the goal without that cost.

**One observation I cannot attribute.** In the deep tier, the furthest training step my bots reach
shifted from a spread of {6, 9, 10} in v1.7.15 to a hard cluster at **7** in v1.7.18 — no bot passed
step 7. Driving it by hand I got through step 8 to step 9 without trouble, so the flow is passable;
and the paired boot/FPS numbers rule out a slowdown as the cause. It may be my harness reacting to
the v1.7.16–17 surface-ordering changes. Flagging it rather than calling it a defect — but if you
changed anything about how step 7's Planetside dismiss hands off to the Compendium, that is where
I would look first.

## Suggested order

1. **CF1718-01** — one identifier. It is destroying save data today.
2. **CF1718-03 / -04 / -05** — move three CSS blocks into the second `<style>`. Three of this
   round's fixes start working.
3. **CF1718-02** — swap two expressions for the seeds on the line above.
4. **CF1718-06, -07, -08, -09** — the training-restart cluster.
5. Everything else, then the eight still-open v1.7.15 items.

**A process note worth more than any single item here.** Three fixes this round were written
correctly and placed where they could not run — two CSS blocks in the wrong `<style>` element, one JS
helper out of scope — and all three failed *silently*. A five-line smoke test would have caught every
one: after a change, assert the thing you just fixed. `getComputedStyle(document.getElementById('bell')).width === '44px'`,
and a boot with a `tsnap` save that asserts the training card appears. That is cheaper than another
audit round.
