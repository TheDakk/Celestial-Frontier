# Prepared phone probe — visually rejected candidate

**Preparation only; no device run.** The SDXS candidate is visually rejected for all five subjects in `../VISUAL_REVIEW.md`. This packet is an isolated transport/runtime experiment, with no game wiring, library admission or device qualification.

`manifest.json` binds 20 exact GET routes and their original bytes. The payload is **728,276,005 bytes** against an explicit 1,000,000,000-byte transport cap: 639,130,313 bytes of image models and 236,544 bytes of precomputed CLIP conditioning, plus the client, two ORT support files and five original master/label pairs. Resident memory, peak GPU memory and physical-phone time are unmeasured, not inferred from file size.

The only model routes are encoder, UNet and decoder. The tokenizer, tokenizer configuration and text encoder have no routes. The two ORT files are the exact module/WASM pair observed during the Mac run. The original Mac client bundle is reused byte-for-byte with independently pinned `mode: phone` inputs, so its Mac-only tokenizer/text branch cannot be served by this harness. The embedding matches the successful Mac output, its prompt hash and `[1,77,768]` float32 shape. Originals and Mac evidence remain unchanged.

`../serve-phone.mjs` is an import-safe standalone harness. It opens no browser and never starts inference automatically. Its page requires a manual single press and keeps the rejection visible. A later authorized device run must use a trusted secure context; the harness requires TLS certificate/key arguments for a non-loopback binding. It accepts explicit `--host`, `--port`, `--out`, `--tls-cert` and `--tls-key` pairs. Output must be a new directory below this packet. The harness owns a bounded 15-minute collection window and the workspace lock, captures one copy of each permitted output, and rechecks manifest/source/model/runtime/HEAD hashes at both boundaries. Any later native/device run still requires the lane's reservation and terminal notice.

Requests outside the exact manifest, query/encoded/traversal/range variants, and unlisted writes are refused. It does not serve directories or model-cache paths. Successful output collection applies the unchanged conservation owner and independently checks protected pixels, but **a conservation pass still leaves visual rejection and device qualification false**.

Three focused Node controls pass: manifest/byte-boundary mutations, forbidden route decisions, and the actual HTTP handler. The HTTP control served the exact embedding and refused text/tokenizer, unknown runtime, query, encoded/traversal, range and duplicate-output attempts. Its initial sandbox listener was refused with `EPERM`; the same bounded Node-only control passed with loopback networking enabled. No browser, model session, device or inference ran in those controls. `validation.json` retains that distinction.
