# Opt-in adhesive terminal-pad observers

Read-only source audit, 2026-09-23. This is an implementation review, not a new test, static row, native film, or clearance measurement. The proposed record declaration is `geometry.contactPads` with schema `cf.terminal-pad-support/v1`, kind `adhesive`, and one manually authored source point per contact-chain end. No declaration means the existing path remains unchanged.

## Contract scope

The existing observed-support contract bounds the selected painted anchor drift to **0.25 source pixels** (`creature-rig-contact.ts`, `measure()` and final residual guard). It does not test every sole vertex against a horizontal plane. `groundLineY` admission is a finite normalized-coordinate check in `family-record.mjs`; it does not establish four independent ground planes or terrain clearance. The half-launch source has perspective-separated feet. An adhesive pad point is therefore an anchor, not evidence that the entire foot rests above a global or per-foot floor. No new plane, clearance threshold, or bottommost-mesh-vertex rule is justified by the inspected owners. Transparent mesh padding makes the last rule particularly misleading.

For rendered triangle vertices `v0,v1,v2` and declared barycentric weights `b0,b1,b2`, the observed point is `P = b0*published(v0) + b1*published(v1) + b2*published(v2)`. Compare `hypot((P.x-paintedTarget.x)*width, (P.y-paintedTarget.y)*height)` with the unchanged 0.25-pixel bound. This is rig-local source space: stage facing, placement, camera and scaling must not be applied to only one side of the comparison. Missing or nonfinite samples cannot count as zero drift.

The existing rig applies compiled skin, ARAP and part guards to private pending arrays before publishing all geometry (`creature-rig.ts:174–183`). Preserve that transaction if contact admission is moved into runtime; a check after publication is useful diagnostic evidence but cannot itself preserve last-good rendering on refusal.

## Focused controls for the integration owner

- An anchor lies inside a rendered triangle rather than exactly on a mesh vertex; its reader must return the actual interpolation after deformation.
- The terminal anchor is stable while the ankle-owned mark moves, and vice versa. Only the declared painted anchor determines the terminal-mode drift result.
- Move one contributing published vertex so interpolated drift exceeds 0.25 pixels: the observer must reject despite a successful scalar solver prediction.
- Wrong part/index, empty surface, invalid interpolation and nonfinite published coordinates must fail closed; disposed/unpublished readers keep their documented null result.
- A refused pending pose must leave previous published support unchanged; recovery must observe the next successfully published pose with its matching contacts.
- Default records retain their existing single-vertex path and exact S2 outputs. This review executed no such controls.
