This proposal follows the two exact first-contact refusals. No production edit or changed-policy sample has been executed by this diagnostic.

Use an explicit optional contract declaration `contactStance.swingLift: 'toward-socket'`. Accept the field only for the `myriapod` family with `anatomyModel: 'myriapod-rigid-trunk-v1'` and resolved source-owned fixed sockets. Unknown values, foreign models/families and missing socket geometry refuse. Omission retains the exact existing screen-up path for every old family and record; do not globally reinterpret any foot above its parent.

For the opted compact model, retain the current swing ownership, signed-step clock, interpolation, weight, horizontal retraction and numerical lift amplitude. The existing vertical amplitude is `sin(pi * at)^2 * lowerLength * 0.15 * weight`. Its source-space direction is `sign(socket.y - endpoint.y)`; add that signed amplitude to the source endpoint y. Above-trunk feet therefore swing down toward the trunk and below-trunk feet retain upward swing. A source-horizontal endpoint has zero projected vertical component. This is a fixed source-layout convention, not an adaptive optimizer or a response to a failed solve. It does not recompute direction from an accommodated/moving root.

Only active synthetic swing targets use this declaration. Planted targets, gait-policy-released authored limbs, stage travel and body-planted folded support keep their existing ownership. The convention does not add vertical root accommodation or change the original 8% cap, bone lengths, joint limits, endpoint tolerance, painted-point tolerance, action timing or .15/.10 lift/retraction factors.
