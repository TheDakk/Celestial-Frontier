# C41 stage admission and phone delivery — 2026-09-26

Implemented on the OpenAI Mac lane after merge `86ee9347`. This is an opt-in admission seam, not game routing or quality acceptance. No source master, original build pin, record, binding, atlas, conservation rule, published library manifest or finished delivery entry was changed.

## Stage contract

`admitCreatureFinishedAtlasV1(pinnedInput, source, original, labelsPng)` in `apps/game/src/creature-finish-admission.ts`:

1. Requires an exact private bundled rig pin; snapshots the input bytes, record, source and original before its first await.
2. Runs the complete existing `preflightBattle2PinnedBytesV1` on original record, alpha, decompressed binding and atlas bytes, with original paths and hashes.
3. Requires source master PNG/recipe/dimensions to equal that genuine pin, and source binding to equal the exact pinned bytes.
4. Authenticates the original labels PNG against a supplementary bundled labels pin tied to the current full-record hash and canonical fit path. Decoded labels must exactly equal the engine source labels, not merely a caller-provided label hash.
5. Runs the existing phone-tier engine reader over the supplied retained original. It constructs no model, writes nothing and reruns original identity, receipt, PNG and unchanged conservation checks against the authenticated source.
6. Uses Claude's `projectFinishedToAtlasV1` on the original atlas and original binding frames; the private WeakMap keeps the resulting pixels. The returned frozen token exposes only key, original hash and creature id. A JSON/spread clone has no authority.

`loadPinnedCreatureRigV1(input, decoder, {finishedAtlas:{token,identity}})` still admits its original bytes and semantic record, then requires the token's exact rig pin and intended individual identity before using the private pixel callback. It takes the same binding/parts/skin/seam allocation tail. No new atlas hash is substituted into the record or binding. Unchecked `atlasPixels` composition and borrowed-texture ownership are refused when a finish is supplied; native paint-skin frames are required. The unpinned loader refuses this option. Joint-scale morphs remain independent existing options.

**Why an additional labels registry:** G3's current 521-file manifest contains zero `labels.png` entries. The new `creature-finish-source-pins.generated.ts` therefore supplies label authority without relying on a caller's hash. Regenerate/check from the repo root:

```sh
node port/v2/tools/morph/creature-finish-source-pins.mjs
node port/v2/tools/morph/creature-finish-source-pins.mjs --check
```

All 38 original rig identities are represented. **34 have labels evidence; four deliberately refuse** because their canonical fit labels are missing in this checkout: Civet (`civet-sentinel-input-01`), Eel (`fit-02`), Rat (`fit-03`), Salamander (`fit-05`). No labels were fabricated or borrowed from another fit. Labels still need transport by the caller; their verified pin is now available through `creatureFinishLabelsPinV1`. No labels or masters were added to the PWA/library pack. A changed original record makes the supplementary pin stale and refuses until regenerated from reviewed source evidence.

## Phone delivered-original contract

`createCreatureFinishDeliveryV1({base?,fetchImpl?})` returns the engine's delivery callback. The callback derives paths exclusively from the exact four-field `creatureOriginalKey(identity)`:

- `library/creature-finish/<key>/original.png`
- `library/creature-finish/<key>/receipt.json`

**Both** must have byte-size and SHA entries under G3's existing bundled manifest authority. There is no caller manifest-pin, arbitrary path or expected-hash option. The adapter checks PNG <=8 MiB, receipt <=1 MiB, receipt schema/key/exact identity and receipt output hash equal to the pinned PNG. It returns null when either entry is absent or the manifest is unavailable; corrupt delivered bytes or identity throw into the existing engine fallback. The engine must still validate source identity, pinned labels/binding and conservation before retaining or displaying that row. A pinned receipt is provenance, never authority to replace original rig input.

No actual finished entries are published by this batch. Claude can supply this callback to the routing layer when reviewed finished originals and their receipts are intentionally included in a future library build. Phones construct no finisher through this seam.
